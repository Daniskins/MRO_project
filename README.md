# MRO Service — учёт ТО и наработки БПЛА (FastAPI)

Backend-платформа для учета и управления техническим обслуживанием (ТО) и наработкой беспилотных летательных аппаратов (БПЛА).

Проект разрабатывается как **инженерный pet-проект и портфолио**, с фокусом на промышленный подход, чистую архитектуру и масштабируемость, а не на «учебный CRUD».

---

## О проекте

В сфере эксплуатации БПЛА до сих пор широко используются Excel-таблицы, ручной учет наработки и разрозненные системы.
Цель проекта — **спроектировать backend-основу сервиса учёта ТО/наработки БПЛА**, которая:

- отражает реальные бизнес-сущности
- легко расширяется
- не привязана к конкретному фронтенду
- готова к интеграции аналитики и ML-модулей

---

## Технологический стек

- **Python 3.11+**
- **FastAPI** — высокопроизводительный REST API
- **SQLAlchemy 2.0 (async)** — современная ORM
- **Alembic** — контроль версий схемы БД
- **Pydantic v2** — строгая валидация данных
- **PostgreSQL** 
- **Uvicorn**

---

## Архитектурные принципы

Проект строится с опорой на практики, используемые в реальных backend-системах:

- четкое разделение слоев:
  - API (FastAPI routers)
  - бизнес-логика (CRUD / сервисы)
  - модели данных
  - инфраструктура
- минимизация связности между модулями
- предсказуемые зависимости
- готовность к росту проекта без переписывания ядра

Архитектура изначально проектировалась так, чтобы в дальнейшем можно было добавить:
- роли и авторизацию
- аудит операций
- WebSocket-уведомления
- аналитические и ML-модули
- возможно телеграмм-бот для уведомлений

## Доменная модель

- **Uav** — карточка БПЛА (модель, серийный/бортовой номер, эксплуатант, место базирования, статус, суммарная наработка).
- **OperatingTimeLog** — журнал наработки: запись о каждом вылете/сессии (дата, часы, кол-во циклов). При добавлении записи суммарная наработка БПЛА пересчитывается автоматически.
- **MaintenanceType** — справочник видов ТО с периодичностью по наработке (часы) и/или по календарю (дни).
- **MaintenanceRecord** — фактически выполненное ТО по конкретному БПЛА; при указании вида ТО срок следующего обслуживания (по часам и/или по дате) рассчитывается автоматически.

Эндпоинт `GET /api/uavs/{uav_id}/maintenance-status` возвращает наработку аппарата относительно следующего планового ТО и признак просрочки.

## Текущий статус

Проект находится в активной разработке. На данный момент реализованы:
- базовая структура проекта
- модели данных для БПЛА, журнала наработки и ТО (справочник видов + фактические записи)
- CRUD-операции и REST API для всех сущностей
- расчёт статуса ТО (просрочено/нет) по наработке и календарю
- миграции Alembic
- базовые роутеры FastAPI

В планах:
- веб-страницы списка БПЛА, журнала наработки и записей ТО (сейчас есть только REST API + форма добавления БПЛА)
- роли и авторизация
- Docker-контейнеризация
- уведомления о приближающемся/просроченном ТО
